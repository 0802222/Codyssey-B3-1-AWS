# Codyssey-B3-1-AWS

# 과제 개요

## 1. 클라우드 인프라 개념
- 클라우드는 인터넷 위에 서버, 네트워크, 저장 공간을 빠르게 만드는 서비스다.
- 쉽게 말해, 직접 장비를 사서 설치하지 않아도 필요한 서버를 바로 빌려 쓸 수 있는 환경이다.
- 이번 미션의 핵심은 웹 서버를 띄우는 것만이 아니라, 안전하게 연결하고 안전하게 운영할 수 있는 구조를 만드는 것이다.

## 2. 네트워크 구성 요소
- VPC(Virtual Private Cloud): AWS 안에서 우리만 쓰는 가상 네트워크 공간이다.
- 쉽게 말해, 클라우드 안에 만든 전용 구역이다.
- Subnet(서브넷): VPC를 더 작은 구역으로 나눈 공간이다.
- Route Table(라우트 테이블): 트래픽이 어디로 가야 하는지 적어 둔 길 안내표다.
- Internet Gateway(인터넷 게이트웨이): VPC와 인터넷을 이어 주는 문이다.
- 흐름은 보통 외부 요청 -> Internet Gateway -> Route Table -> Public Subnet -> EC2 웹 서버 순서로 이어진다.

## 3. 컴퓨트와 웹 서버 배포
- EC2(Elastic Compute Cloud): AWS에서 빌려 쓰는 가상 서버다.
- 쉽게 말해, 실제 프로그램이 설치되고 실행되는 컴퓨터 한 대라고 생각하면 된다.
- Public Subnet에 EC2를 두고 퍼블릭 IP를 받으면 외부에서 접속할 수 있다.
- 웹 서버는 Nginx 같은 프로그램으로 띄우며, 인스턴스 안에서는 `curl http://localhost`가 200 응답을 돌려줘야 한다.

## 4. 보안 그룹과 접근 제어
- Security Group(보안 그룹)은 서버 앞에서 출입을 막고 허용하는 가상 방화벽이다.
- HTTP 80 포트는 웹 페이지를 보여주기 위해 외부에 열어 둔다.
- SSH 22 포트는 서버에 직접 들어가는 문이므로, 내 IP에서만 접속되게 제한한다.
- `0.0.0.0/0`에 모든 포트를 열어 두지 않는 것이 기본 원칙이다.

## 5. IAM 최소권한
- IAM(Identity and Access Management)은 AWS 자원에 누가 무엇을 할 수 있는지 정하는 권한 관리 기능이다.
- 쉽게 말해, AWS에서 열쇠를 누가 얼마나 가질지 정하는 제도다.
- AdministratorAccess 같은 전체 권한은 쓰지 않는다.
- 이번 실습에 필요한 EC2, VPC, Security Group 생성, 조회, 태그, 연결 권한만 허용한다.
- 최소권한 원칙은 꼭 필요한 만큼만 권한을 주어 실수나 침해 피해를 줄이는 방법이다.

## 6. 외부 접속 검증
- 외부에서 정말 열려 있는지 확인해야 한다.
- 방법 A: 브라우저에서 `http://<퍼블릭IP>`에 접속해 화면이 뜨는지 본다.
- 방법 B: `GET http://<퍼블릭IP>/health`를 호출해 200 응답과 고정 메시지를 확인한다.
- README에는 선택한 방법과 접속 주소를 적어 둔다.

## 7. 트러블슈팅 사고방식
- 증상: 무엇이 안 되는지 먼저 적는다.
- 가설: 보안 그룹, 라우팅, 퍼블릭 IP, 웹 서버 상태 중 어떤 문제인지 추측한다.
- 검증: 로그와 설정을 보고 가설이 맞는지 확인한다.
- 조치: 잘못된 설정을 고친다.
- 결과: 다시 접속해서 문제가 해결됐는지 본다.
- 재발 방지: 같은 실수를 막기 위해 체크리스트에 적는다.

## 8. 과금 방지와 리소스 정리
- 실습이 끝나면 만든 자원을 꼭 지워야 돈이 더 나오지 않는다.
- EC2, EBS(Elastic Block Store, 블록 저장소), Elastic IP, Internet Gateway, VPC를 정리한다.
- NAT Gateway, ELB/ALB, RDS를 썼다면 그것도 삭제 여부를 확인한다.
- 마지막으로 Billing Dashboard를 보고 남은 과금 위험이 없는지 확인한다.

## 9. 제출 산출물 요약
- 아키텍처 다이어그램: VPC, Subnet, Internet Gateway, EC2, Security Group, 외부 트래픽 흐름이 보이도록 만든 그림
- 외부 접속 증빙: 브라우저 화면 또는 `/health` 응답 스크린샷
- 트러블슈팅 보고서: 문제, 원인 추측, 확인, 수정, 결과, 재발 방지를 적은 문서
- 리소스 정리 체크리스트: 종료와 삭제가 끝났다는 근거를 적은 문서
