# Trouble Shooting

### 1. 리전 불일치

| 항목 | 내용 |
| -- | -- |
| 증상 (문제상황) | EC2 생성 과정에서 기존 VPC를 연결하려 했으나 VPC 목록에 표시되지 않음 |
| 원인 가설 | VPC와 EC2가 서로 다른 리전에 설정되었을 가능성이 있음 |
| 검증 방법 | VPC의 리전 설정을 확인한 결과, 해당 VPC가 시드니 리전에 생성되어 있음을 확인함 |
| 조치 내용 | 리소스 정리 과정을 기록한 스크린샷이 필요했으므로 시드니 리전의 리소스를 정리할 때까지 유지한 후 삭제함 |
| 결과 | 리소스 정리 과정은 시드니 리전에서 진행하고, 실제 시연은 서울 리전에서 진행함 |
| 재발 방지 | AWS 리소스를 생성하거나 연결하기 전에 대상 리전을 반드시 확인함 |

### 2. PEM 키 페어 불일치
| 항목 | 내용 |
| -- | -- |
| 증상 (문제상황) | EC2 인스턴스에 SSH로 접속하는 과정에서 PEM 키를 입력했으나 `permission denied` 오류가 발생함 |
| 원인 가설 | EC2 생성 시 지정한 키 페어와 SSH 접속에 사용한 PEM 키가 서로 다를 가능성이 있음 |
| 검증 방법 | EC2 인스턴스에 지정된 키 페어 이름과 로컬 PEM 키를 대조한 결과, 서로 다른 키 페어임을 확인함 |
| 조치 내용 | 기존 PEM 키를 삭제하고, EC2에 지정된 키 페어에 대응하는 PEM 키를 재발급한 후 해당 키를 사용해 접속함 |
| 결과 | 재발급한 PEM 키를 사용하여 SSH 로그인에 성공함 |
| 재발 방지 | EC2 생성 직후 지정된 키 페어와 PEM 키 파일을 기록하고, 접속 전에 키 페어 이름과 파일 권한(`chmod 400`)을 확인함 |
